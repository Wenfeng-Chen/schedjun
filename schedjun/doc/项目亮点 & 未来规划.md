# 项目亮点 & 未来规划

---

## 项目亮点

### 1. 两段式确认机制，防误操作

AI 不会直接写入数据库。用户语音输入后，系统先返回 `scheduleDraft`（日程草稿）展示确认卡片，用户点击「确认」后才真正执行增删改。

- **创建**：展示标题 + 时间范围，确认后写入
- **修改**：对比新旧值，确认后更新
- **删除**：红色警告「此操作不可撤销」，确认后永久删除

语音输入天然易出错，确认机制是体验兜底的关键设计。

---

### 2. AI 小人，可拖拽

助手界面有一个可交互的 AI 形象（小人），支持手指拖拽移动。不只是静态图标，而是让用户感觉"在跟一个活的东西对话"，增加趣味性和品牌记忆点。

---

## 未来规划

### 基础档

#### 1. 语音播报（TTS）

当前 AI 回复只以文字形式展示。接入 TTS（文本转语音），让「君听」把回复读出来：

> 用户："明天下午三点开会"  
> 君听（语音）：「好的，已为你备好日程——6月13日 15:00 开会，确认创建吗？」

免提场景（开车、做饭）下不用看屏幕也能完成交互。

---

#### 2. AI 功能扩展——更强的数据处理能力

不止增删改查，让 AI 能理解和回答复杂问题：


| 场景       | 示例                                 |
| -------- | ---------------------------------- |
| **统计查询** | "我这周开了多少会？" → 统计本周标题含"会议"的日程数量     |
| **时间分析** | "我哪天最忙？" → 按天聚合日程时长，找出日程密度最高的一天    |
| **空闲查找** | "明天下午我什么时候有空？" → 扫描次日空白时段，返回可用时间窗口 |
| **模糊回忆** | "上个月我是不是有个聚餐？" → 关键词检索历史日程，返回匹配结果  |
| **条件筛选** | "下周有哪些带提醒的日程？" → 按提醒规则筛选下周日程       |


后端新增 `/assistant/query` 端点，AI 解析意图后走结构化查询返回结果。

---

#### 3. AI 小人互动增强

在可拖拽基础上增加更多交互反馈：


| 动作         | 反馈                         |
| ---------- | -------------------------- |
| **点击小人**   | 弹出快捷操作菜单（创建日程 / 查看今日 / 闲聊） |
| **拖拽到角落**  | 小人缩小为悬浮球，不遮挡界面             |
| **说话时**    | 小人有聆听动画（如点头、波形抖动）          |
| **分析完成时**  | 小人弹出确认卡片，手指指向卡片方向          |
| **长时间不操作** | 小人打哈欠 / 东张西望（趣味待机动画）       |


让 AI 形象从静态图标变成有"生命力"的交互角色。

---

#### 4. 月视图迷你预览

当前月视图只能看到日期数字，需要逐一点击才能知道哪天有日程。增强为格子内直接预览：

- **彩色圆点**：当天有日程时，日期格子内显示小圆点（不同颜色区分类型：工作 / 个人 / 其他）
- **缩略标题**：有足够空间时显示日程标题的前几个字（如"开会…""聚餐"）
- **空白日期**：无日程的格子保持干净，一眼分辨忙碌与空闲

不用逐一点开，扫一眼月视图就知道本月哪天有事哪天空闲。

### 进阶档

#### 1. 桌面小组件（Widget）

在手机桌面直接放置日程小组件，类似天气组件，无需打开 App：


| 规格          | 内容               |
| ----------- | ---------------- |
| **小尺寸 2×2** | 显示最近一条日程的时间 + 标题 |
| **中尺寸 4×2** | 显示今天全部日程列表       |
| **大尺寸 4×4** | 显示本周日历热力图 + 今日摘要 |


每天解锁手机就能看到今天要干什么，降低打开 App 的心理门槛。

---

#### 2. AI 智能安排建议（征求式）

用户主动询问 AI 意见时，AI 给出安排建议并等待用户确认，从"被动执行"升级为"主动参谋"：

**典型对话流程：**

> 用户："下周我要准备答辩、改论文、还要跟导师开会，你帮我看看怎么安排"  
> 君听：「分析了一下你的下周空闲时段，建议：周一上午改论文，周二下午 3 点跟导师开会，周三到周五集中准备答辩。你觉得呢？」  
> 用户："可以" / "把答辩提前一天"  
> 君听：调整建议 → 用户确认 → 一次性创建多条日程

**核心逻辑：**

1. 用户用自然语言描述任务需求和时间约束
2. AI 扫描已有日程 + 用户空闲时段
3. AI 生成一份包含多条日程的安排方案
4. 以结构化草稿（类似 `scheduleDraft[]`）返回前端展示
5. 用户确认后一次性批量创建

从「用户一条一条说」变成「用户说需求，AI 出方案，用户点头」，大幅降低复杂场景下的交互轮次。

---

#### 3. 语音唤醒

用户不用打开 App 或点击按钮，直接说出唤醒词即可触发语音助手：

> "嘿，君听" → App 被唤醒，进入聆听状态  
> "明天下午三点开会" → ASR 转录 → AI 分析 → 确认  

配合语音播报（TTS），实现**纯语音交互闭环**——从唤醒到确认全程不需要碰手机。车机模式、厨房场景下的体验质变。
